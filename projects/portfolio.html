Portfolio Website Redesign

I redesigned and rebuilt my personal portfolio.

Role
Design and Development
Timeline
2026
Tools
Figma, HTML, CSS, JavaScript, AI tools

Problem

The first portfolio was built quickly with messy code, inconsistent layout, and no accessibility planning.

Goal

Rebuild the site from scratch with a proper design system, clean code, and WCAG AAA accessibility.

My Role

Full design and development: Figma layout, design tokens, HTML, CSS, JavaScript, and content.

Outcome

A professional portfolio with consistent structure, strong contrast, responsive layout, and clear hierarchy.

Overview

This project is a complete redesign of my personal portfolio website. The earlier version was built quickly during a learning phase. It worked at first glance, but the code was messy, the layout was inconsistent, and accessibility was not considered.

I decided to start fresh. I designed a new layout system in Figma, defined spacing and typography tokens, and rebuilt the site with clean HTML and CSS. The result is a professional portfolio with consistent structure, strong contrast, and clear content hierarchy.

The redesign also gave me a chance to combine AI tools with my own front-end and design skills. I used AI to speed up certain tasks, but all design decisions and final implementation choices were mine.

Problem and Starting Point

The first version of my portfolio was built without a design system or clear plan. I was learning as I went, and the result showed it. The code worked, but it was hard to maintain and extend.

  • Layout was inconsistent across different sections and pages
  • Colors and font sizes were chosen without a system
  • Contrast ratios did not meet accessibility standards
  • Content structure had no clear hierarchy for scanning
  • CSS had no organization, making changes risky
  • The site did not present my work in a professional way

The portfolio needed more than small fixes. It needed a full rethink of structure, content, and visual design.

Goals and Requirements

Before starting the redesign, I wrote down clear goals. These guided every decision during the process.

  • Clear structure and content hierarchy on every page
  • Easy to scan for recruiters and hiring managers
  • WCAG AAA contrast ratio (7:1 minimum) on all text
  • Minimum 1rem font size for all body text
  • Consistent design system with defined tokens for spacing, colors, and typography
  • Responsive layout from 320px to wide screens
  • Good performance without heavy frameworks
  • Minimal and calm visual style that puts content first

Design Process in Figma

I started the redesign in Figma before writing any code. This helped me think about layout, spacing, and visual hierarchy without getting distracted by implementation details.

  • Created a spacing scale from xs to 3xl
  • Defined a typography system with consistent sizes and weights
  • Designed reusable components for cards, sections, and navigation
  • Tested color combinations to meet AAA contrast requirements
  • Iterated on the hero section, case study cards, and about section
  • Designed mobile and desktop layouts side by side

The Figma file became the single source of truth for the project. Every value in the CSS maps back to a decision made in Figma.

Development and Refactoring

The CSS was rebuilt from scratch with a clear architecture. I organized it into numbered sections so that any part of the code is easy to find and update.

  • All visual values use CSS custom properties (design tokens)
  • HTML uses semantic elements: header, nav, main, section, aside, footer
  • Consistent container and spacing system across all pages
  • Responsive behavior uses clear, consistent breakpoints
  • All text meets minimum 1rem font size
  • All color combinations pass WCAG AAA contrast (7:1)
  • Improved hover and focus states for keyboard navigation
  • Case study pages share a common template structure

The refactoring was iterative. I built each section, tested it across screen sizes, checked contrast, and then moved to the next.

Use of AI in the Workflow

I used AI tools as a development partner during this project. AI helped with specific tasks, but the creative direction and final decisions were always mine.

  • Used AI to refine and structure case study content
  • Ran systematic accessibility audits checking contrast and font sizes
  • Used AI to help reorganize CSS into a clean, commented architecture
  • Combined AI suggestions with my own front-end knowledge
  • Reviewed every output and made manual corrections where needed

Key principle: AI made the work faster, but it did not make the decisions. I directed the process, chose what to keep, and took responsibility for the result.

Key Decisions and Trade-offs

Several decisions shaped the final result. Each one involved balancing different priorities.

  • Simplified the visual language to focus on content clarity
  • Removed decorative elements that did not serve the user
  • Chose AAA contrast over AA, which limited color options but improved readability
  • Used plain HTML, CSS, and JS instead of a framework to keep the site fast and simple
  • Avoided heavy animations that could distract from the content
  • Kept one well-organized CSS file instead of multiple imports
  • Balanced design quality with technical feasibility for a solo project

Results and Improvements

The redesigned portfolio is better in every measurable way compared to the first version.

  • Clear content hierarchy that guides the reader through each page
  • Better readability with consistent typography and spacing
  • All text passes WCAG AAA contrast requirements
  • All body text uses at least 1rem (16px) font size
  • Consistent design system across all pages
  • Responsive layout from mobile to ultrawide screens
  • Keyboard navigation and focus management work correctly
  • Stronger personal brand and more professional presentation
  • Reduced motion support for users who prefer less animation

Lessons Learned

This project taught me several things that I will carry into future work.

  • Structure and hierarchy should come before visual styling
  • Accessibility is not something to add later. It must be planned from the start
  • A design system with tokens saves time and reduces inconsistency
  • Designing in Figma first makes development faster, not slower
  • Iteration improves clarity. The first version is rarely the best version
  • AI is useful for specific tasks, but it needs clear direction and careful review
  • Testing contrast and font sizes systematically catches issues that visual review misses
