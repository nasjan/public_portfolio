Meal Macro Builder

A reactive web application for building meals and tracking nutrition. I built this full-stack project to learn cloud services, authentication, and real-time database integration. Reaktiivinen verkkosovellus aterioiden rakentamiseen ja ravinnon seurantaan. Rakensin tämän full-stack-projektin oppiakseni pilvipalveluista, autentikoinnista ja reaaliaikaisesta tietokantaintegraatiosta.

ProblemOngelma

Tracking macros is slow and complicated. Most tools have too many features for everyday use. Makrojen seuraaminen on hidasta ja monimutkaista. Useimmissa työkaluissa on liikaa ominaisuuksia arkikäyttöön.

GoalTavoite

Build a simple meal builder that calculates nutrition in real time and saves meals for each user. Rakentaa yksinkertainen aterian kokoaja, joka laskee ravintosisällön reaaliajassa ja tallentaa ateriat kullekin käyttäjälle.

My RoleRoolini

React frontend development, and Firebase backend integration (Auth & Firestore) React-käyttöliittymän kehitys ja Firebase-backend-integraatio (Auth & Firestore)

OutcomeLopputulos

A functional MVP tested with 7 users. It achieves high Lighthouse performance scores and works seamlessly across mobile and desktop devices. Toimiva MVP testattuna 7 käyttäjällä. Saavuttaa korkeat Lighthouse-pisteytykset ja toimii saumattomasti sekä mobiili- että työpöytälaitteilla.

OverviewYleiskatsaus

This is a beginner level React application that I built as a personal tool. I wanted to create something I would actually use every day. At the same time, I wanted to learn how a real web application is planned, designed, and built as an MVP.

The idea of a meal macro calculator is not new. My focus was on understanding how to build one from scratch. It was built as a coursework assignment for the "Cloud Services in Web Development" module at Haaga-Helia UAS.

Tämä on aloittelijan tason React-sovellus, jonka rakensin henkilökohtaiseksi työkaluksi. Halusin luoda jotain, mitä käyttäisin oikeasti joka päivä. Samalla halusin oppia, miten todellinen verkkosovellus suunnitellaan, toteutetaan ja rakennetaan MVP:nä.

Makrolaskurin idea ei ole uusi. Fokukseni oli ymmärtää, miten sellainen rakennetaan alusta asti. Se rakennettiin kurssin tehtävänä Haaga-Helian "Pilvipalvelut web-kehityksessä" -moduulille.

Problem and ContextOngelma ja konteksti

While there are many mobile apps for nutrition, they usually require installation and heavy updates. I wanted to create a lightweight web application that runs directly in the browser without any app store downloads.

The goal was to build a fast "single view" tool. The user adds ingredients, types in the grams, and the nutrition totals update instantly. The challenge was to implement this reactive logic and real-time database connection in a simple web interface.

Vaikka ravitsemussovelluksia on paljon, ne vaativat yleensä asennuksen ja raskaita päivityksiä. Halusin luoda kevyen verkkosovelluksen, joka toimii suoraan selaimessa ilman sovelluskauppalatauksia.

Tavoitteena oli rakentaa nopea "yksinäkymä"-työkalu. Käyttäjä lisää ainesosia, kirjoittaa grammat ja ravintosisältö päivittyy välittömästi. Haasteena oli toteuttaa tämä reaktiivinen logiikka ja reaaliaikainen tietokantayhteys yksinkertaisessa verkkokäyttöliittymässä.

Research and InsightsTutkimus ja havainnot

I researched how to make a web app feel as smooth as a native mobile app. I wanted the user experience to be seamless, even though it runs in a browser.

  • Speed is key: The app must load quickly and react immediately to input changes.
  • Simplicity: Moving between building a meal and reviewing meals should be clear
  • Accessibility: The interface needs to work well on both mobile phones and desktop computers without breaking the layout.

Key insight: Users appreciate a tool that opens instantly in a browser and does one thing very well, rather than a complex app with too many features.

Tutkin, miten verkkosovellus saadaan tuntumaan yhtä sujuvalta kuin natiivi mobiilisovellus. Halusin, että käyttökokemus on saumaton, vaikka sovellus toimii selaimessa.

  • Nopeus on avain: Sovelluksen on ladattava nopeasti ja reagoitava välittömästi syötteiden muutoksiin.
  • Yksinkertaisuus: Aterian rakentamisen ja tallennettujen aterioiden välillä siirtymisen on oltava selkeää.
  • Saavutettavuus: Käyttöliittymän on toimittava hyvin sekä mobiilipuhelimilla että pöytätietokoneilla rikkoutumatta.

Keskeinen havainto: Käyttäjät arvostavat työkalua, joka avautuu välittömästi selaimessa ja tekee yhden asian erittäin hyvin, mieluummin kuin monimutkaista sovellusta, jossa on liikaa ominaisuuksia.

Ideation and DecisionsIdeointi ja päätökset

I designed the MVP around one main flow: search for food items, enter grams, see nutrition totals update in real time, and save the meal. I used Nielsen heuristics to guide interface decisions. I focused on showing system status, preventing errors, and giving users control.

  • Show feedback right away for important actions
  • Use the same patterns on every page so users learn quickly
  • Use readable fonts and clear contrast for basic accessibility

Suunnittelin MVP:n yhden päävirran ympärille: hae ruoka-aineita, syötä grammat, katso ravintosisällön yhteensä päivittyvän reaaliajassa ja tallenna ateria. Käytin Nielsenin heuristiikkoja ohjaamaan käyttöliittymäratkaisuja. Keskityin järjestelmätilan näyttämiseen, virheiden ehkäisemiseen ja käyttäjien kontrollin antamiseen.

  • Näytä palaute välittömästi tärkeille toiminnoille
  • Käytä samoja malleja jokaisella sivulla, jotta käyttäjät oppivat nopeasti
  • Käytä luettavia fontteja ja selkeää kontrastia perustavanlaatuiseen saavutettavuuteen

Design SolutionSuunnitteluratkaisu

I kept the design intentionally simple. My primary focus was on the technical implementation, such as connecting React components to the Firebase backend.

This serves as a functional demo (MVP). I believe it is better to focus on the UI details only after the core features are finalized and the user flows are validated.

  • React components for the meal builder and saved meals views
  • Real time calculation when users change input values
  • Firestore storage that keeps each user's data separate
  • Clear separation between building a meal and viewing saved meals
  • Same navigation and layout on every page

Pidin suunnittelun tarkoituksellisesti yksinkertaisena. Pääfokukseni oli teknisessä toteutuksessa, kuten React-komponenttien yhdistämisessä Firebase-backendiin.

Tämä toimii toimivana demona (MVP). Uskon, että käyttöliittymän yksityiskohtiin kannattaa keskittyä vasta sen jälkeen, kun ydintoiminnot on viimeistelty ja käyttäjävirrat on validoitu.

  • React-komponentit aterian rakentajalle ja tallennettujen aterioiden näkymille
  • Reaaliaikainen laskenta, kun käyttäjät muuttavat syöttöarvoja
  • Firestore-tallennus, joka pitää jokaisen käyttäjän tiedot erillään
  • Selkeä erottelu aterian rakentamisen ja tallennettujen aterioiden katselun välillä
  • Sama navigointi ja asettelu jokaisella sivulla

Validation and IterationValidointi ja iterointi

I tested the app with seven people aged 25 to 55. All testers said the idea and navigation were clear. They could move between pages without extra help.

  • Found two mobile scaling issues on specific devices and fixed them with CSS changes
  • Fixed iOS Safari auto zoom on inputs by making the font size at least 1rem
  • Tested responsiveness with Chrome DevTools at different screen sizes
  • Tested on Chrome, Edge, and iOS Safari

Iteration highlight: Two testers had trouble with input fields on smaller phones. Making the font size 16px / 1rem fixed the iOS Safari zoom problem and improved usability on all mobile devices.

Testasin sovelluksen seitsemällä henkilöllä ikäryhmässä 25–55. Kaikki testaajat sanoivat, että idea ja navigointi olivat selkeitä. He pystyivät siirtymään sivujen välillä ilman lisäapua.

  • Löydettiin kaksi mobiiliskaalausongelmaa tietyillä laitteilla ja korjattiin ne CSS-muutoksilla
  • Korjattiin iOS Safarin automaattinen zoom syöttökenttiin tekemällä fonttikooksi vähintään 1rem
  • Testattiin responsiivisuus Chrome DevToolsilla eri näyttökokoilla
  • Testattiin Chromella, Edgellä ja iOS Safarilla

Iterointikohde: Kahdella testaajalla oli vaikeuksia syöttökenttien kanssa pienemmillä puhelimilla. Fonttikoon muuttaminen 16 pikseliin / 1rem korjasi iOS Safarin zoom-ongelman ja paransi käytettävyyttä kaikilla mobiililaitteilla.

Results and LearningsTulokset ja oppiminen

Lighthouse testing showed good performance and accessibility scores for an MVP. The app ran smoothly during typical use without visible slowdowns.

  • All 7 testers understood the main flow without instructions
  • Fixed mobile scaling issues on two devices with CSS improvements
  • Confirmed correct behavior on Chrome and Edge
  • Lighthouse scores were strong for both performance and accessibility

This project taught me how to connect a React frontend to a serverless backend and how to solve browser-specific bugs through user testing.

Future improvements include planning meals by day, a history view, more UI improvements, and possibly connecting to a REST API.

Lighthouse-testaus osoitti hyvät suorituskyky- ja saavutettavuuspisteet MVP:lle. Sovellus toimi sujuvasti tyypillisessä käytössä ilman havaittavia hidastumisia.

  • Kaikki 7 testaajaa ymmärsivät päävirran ilman ohjeita
  • Korjattiin mobiiliskaalausongelmat kahdella laitteella CSS-parannuksilla
  • Vahvistettiin oikea toiminta Chromella ja Edgellä
  • Lighthouse-pisteet olivat vahvat sekä suorituskyvyn että saavutettavuuden osalta

Tämä projekti opetti minulle, miten React-käyttöliittymä yhdistetään serverless-backendiin ja miten selainkohtaiset bugit ratkaistaan käyttäjätestauksen kautta.

Tulevat parannukset sisältävät aterioiden suunnittelun päivän mukaan, historianäkymän, lisää käyttöliittymäparannuksia ja mahdollisesti REST API -yhteyden.
