Meal Macro Builder

An MVP web app for building meals and tracking nutrition in real time.

Overview

This project is a beginner level React application designed as a personal everyday tool. The goal was to build something I would genuinely use myself, while learning how a real-world web application is planned, designed, and implemented as an MVP. The concept is familiar and already well established, but the focus was on understanding how such an application is structured and built from scratch.

Project facts

Course: Pilvipalvelut web development (course project)

School: Haaga-Helia University of Applied Sciences

Timeline: MVP built during the course period

Team: Solo project

My role: UX, UI, and front-end implementation

Goal: Build a simple meal builder that calculates nutrition in real time and stores meals per user, while practicing modern front-end fundamentals.

Users: Personal everyday use, validated with usability testing

Methods: MVP scoping, iterative UI refinement, usability testing, responsive and cross-browser QA

Tools and tech: React, Vite, Firebase Authentication, Firestore, Chrome DevTools, Lighthouse

What I built: Login flow, meal builder UI, real-time calculation logic, saved meals view, user-based Firestore storage

Results:

  • Usability testing with 7 participants confirmed that the core flow and navigation were easy to understand without instructions
  • Mobile scaling issues appeared on two devices and were fixed through iterative CSS improvements
  • Cross-browser testing confirmed correct behavior on Chrome and Edge, and iOS Safari issues were resolved by using at least 16 px input font size
  • Lighthouse results showed strong performance and accessibility for an MVP

Problem

Macro tracking is often slow and fragmented. I wanted a lightweight tool where I can quickly build a meal from familiar items, adjust grams, and immediately see the nutritional totals. The UX challenge was to keep the workflow obvious and fast, while still supporting saving and returning to meals later.

Solution

I designed an MVP around one primary flow. Search and add food items, input grams, review real-time nutrition totals, and save the meal for later. The UI is intentionally minimal so users can understand the system without onboarding or instructions.

  • Real-time feedback while editing grams
  • Clear separation between building a meal and reviewing saved meals
  • Consistent navigation and predictable layout across views

UX and UI decisions

The interface was designed for clarity and low cognitive load. Key decisions were guided by Nielsen heuristics, especially system status visibility, error prevention, and user control. The app provides immediate feedback for actions like adding items and saving meals, and the navigation stays consistent across pages.

  • Immediate feedback for key actions to reduce uncertainty
  • Predictable patterns across pages to reduce learning effort
  • Readable typography and clear contrast to support basic accessibility needs

Technical implementation

The application is built with React and Vite. Authentication is handled with Firebase Authentication and user data is stored in Firestore. The data model is intentionally simple to support real-time calculations and maintain readable front-end logic. The focus was on clean structure and maintainable code rather than overengineering.

  • React component structure for builder and saved meals views
  • Real-time calculation logic tied to user input
  • Firestore storage scoped per user

Testing and iteration

Usability was evaluated with seven testers aged 25 to 55. All testers found the idea and navigation clear, and users could move between pages without extra guidance. Two mobile scaling issues were found on specific devices and browsers and were fixed with CSS adjustments. iOS Safari auto-zoom on inputs was resolved by ensuring input font size is at least 16 px.

  • Responsive testing with Chrome DevTools across multiple breakpoints
  • Cross-browser testing on Chrome, Edge, and iOS Safari
  • Performance checked with Lighthouse and DevTools Performance recording

Performance and accessibility

Lighthouse testing showed strong performance and accessibility results for an MVP. Performance recording during typical flows, such as adding items, navigating views, and signing out, showed smooth interactions without noticeable UI jank or long main-thread blocking.

  • Desktop and mobile Lighthouse checks for performance and accessibility
  • DevTools Performance recording during typical user flows

Future development

The project is intended to evolve further as a learning platform. Planned improvements include day-based meal planning, extended history views, continued UI refinement based on testing, and a potential REST API integration later. The next steps are focused on adding value while keeping the product simple and usable.

  • Day plans built from multiple meals
  • Extended history and comparison views
  • Potential REST API integration for additional content
  • Further UI refinement through iterative testing
