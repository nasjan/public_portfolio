Meal Macro Builder

An MVP web app for building meals and tracking nutrition in real time — designed and built as a solo course project.

UX, UI & Front-end

Problem

Macro tracking is slow and fragmented. Existing tools are bloated for everyday meal building.

Goal

Build a lightweight meal builder with real-time nutrition calculations and per-user storage.

My Role

UX research, UI design, and complete front-end implementation as a solo developer.

Overview

This project is a beginner-level React application designed as a personal everyday tool. The goal was to build something I would genuinely use myself, while learning how a real-world web application is planned, designed, and implemented as an MVP.

The concept — a meal macro calculator — is familiar and already well established. The focus was on understanding how such an application is structured and built from scratch.

Problem & Context

Macro tracking is often slow and fragmented. I wanted a lightweight tool where I can quickly build a meal from familiar items, adjust grams, and immediately see the nutritional totals.

The UX challenge was to keep the workflow obvious and fast, while still supporting saving and returning to meals later. This was a course project at Haaga-Helia University of Applied Sciences for the Pilvipalvelut web development module.

Research & Insights

Before building anything I reviewed existing macro tracking tools and identified the common friction points: hidden features behind onboarding, overcomplicated food databases, and multi-step flows just to log a single meal.

  • Users want immediate feedback when adjusting portion sizes
  • Navigation between "building" and "reviewing" should be obvious
  • The app should work instantly without tutorials

Key insight: For a personal daily tool, speed and predictability matter more than feature richness. Every extra step is a reason to abandon the flow.

Ideation & Decisions

I designed the MVP around one primary flow: search and add food items → input grams → review real-time nutrition totals → save the meal. The interface decisions were guided by Nielsen heuristics, especially system status visibility, error prevention, and user control.

  • Immediate feedback for key actions to reduce uncertainty
  • Predictable patterns across pages to reduce learning effort
  • Readable typography and clear contrast for basic accessibility

Design Solution

The UI is intentionally minimal so users can understand the system without onboarding or instructions. The application is built with React and Vite. Authentication is handled with Firebase Authentication and user data is stored in Firestore.

  • React component structure for builder and saved meals views
  • Real-time calculation logic tied to user input
  • Firestore storage scoped per user
  • Clear separation between building a meal and reviewing saved meals
  • Consistent navigation and predictable layout across views

Validation & Iteration

Usability was evaluated with seven testers aged 25 to 55. All testers found the idea and navigation clear, and users could move between pages without extra guidance.

  • Two mobile scaling issues were found on specific devices and fixed with CSS adjustments
  • iOS Safari auto-zoom on inputs was resolved by ensuring input font size is at least 16 px
  • Responsive testing with Chrome DevTools across multiple breakpoints
  • Cross-browser testing on Chrome, Edge, and iOS Safari

Iteration highlight: After testing, two participants struggled with input fields on smaller phones. Increasing font size to 16 px solved the iOS Safari zoom issue and improved usability across all mobile devices.

Results & Learnings

Lighthouse testing showed strong performance and accessibility results for an MVP. Performance recording during typical flows showed smooth interactions without noticeable UI jank.

  • Usability testing with 7 participants confirmed the core flow was easy to understand without instructions
  • Mobile scaling issues on two devices were fixed through iterative CSS improvements
  • Cross-browser testing confirmed correct behavior on Chrome and Edge
  • Lighthouse results showed strong performance and accessibility

Future improvements include day-based meal planning, extended history views, continued UI refinement, and a potential REST API integration.
